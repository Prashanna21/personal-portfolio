# Architecture

## Stack

| Layer | Choice | Version |
|---|---|---|
| Framework | Next.js App Router, Turbopack, React Compiler | 16.3.4 |
| Runtime | React | 19.2.8 |
| Language | TypeScript | 5.9 |
| Styling | Tailwind CSS v4 (CSS-first `@theme`) | 4.3 |
| 3D | three · @react-three/fiber v9 · @react-three/drei v10 | 0.185 |
| Content | MDX via `next-mdx-remote` + `gray-matter` | — |
| Highlighting | `rehype-pretty-code` + `shiki` (build-time, zero client JS) | — |
| Images | `next/image` + `sharp` | — |
| Automation | `playwright-core` driving installed Chrome | — |

> `motion` is installed but only used where CSS genuinely cannot do the job.
> Most animation here is CSS, because CSS runs before hydration.

## Routes

```
/                       home — the full scroll
/work/[slug]            case study  (auth-sync · orbit-chat · vrit · everest-thrills)
/blog                   index + tag filter
/blog/[slug]            post
/cv                     indexable HTML résumé
```

Generated by file convention: `sitemap.ts`, `robots.ts`, `opengraph-image.tsx`,
`icon.svg`, plus a route handler for `rss.xml`.

## Data model

Everything the site says about a project lives in one `Project` object in
`src/data/projects.ts`, consumed by both the home card and the case study page.
Notable fields:

- `embeddable` — verified against live `X-Frame-Options` / CSP headers. Gates
  whether the live-preview iframe is offered at all.
- `offline` — the domain resolves but serves no product. Currently `auth-sync`.
- `shot` — screenshot basename in `public/work/`, or `null` to render the
  designed mock instead.
- `caseStudy` — problem / approach / shipped / stack, used only by `/work/[slug]`.

`src/data/stack.ts` is deliberately one dataset with two coordinate systems:
`x`/`y` (normalised, drives the static SVG fallback) and `z` (lifts nodes into
the R3F scene). See D-005 — the SVG fallback is the SEO-bearing renderer.

## Client/server boundary

Server by default. Client components are only: `Nav`, `ThemeToggle`,
`RevealProvider`, `HeroPortrait`, and the 3D + interactive preview pieces. No
data fetching happens on the client.

## Performance budget

| Metric | Target | Mechanism |
|---|---|---|
| Initial JS (home) | < 105KB gz | 3D, CV viewer and form all dynamically imported |
| LCP | < 1.8s mobile | static render, `priority` portrait, self-hosted fonts |
| CLS | 0 | explicit dimensions everywhere, metric-matched font fallbacks |
| TBT | < 150ms | IntersectionObserver only — no scroll listeners in hot paths |
